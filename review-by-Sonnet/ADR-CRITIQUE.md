# ADR Critique & Recommendations

## ADR-0001: Merge Prompt, Not Replace
**Decision:** Pi system prompt merges lisptc + Pi-specific instructions.
**Assessment:** ✅ Sound. Avoids context thrash.
**Improvement:** Add merge algorithm (prepend, append, override sections?); version prompt hash.

## ADR-0002: Vestige Cabinet (lisptc + cortex)
**Decision:** Vestige stored separately from lisptc compiler state.
**Assessment:** ✅ Good separation of concerns.
**Improvement:** Define cabinet API (read, write, query, compact); add GC policy.

## ADR-0003: Validate Before Eval
**Decision:** All generated code validated before execution.
**Assessment:** ✅ Critical for safety. Underspecified.
**Improvement:** Add validation layers (syntax, type, effect, resource); define toolchain (TS compiler API, custom linter).

## ADR-0004: Reify Replace, Not Accumulate
**Decision:** Vestige reification replaces old state, not accumulates.
**Assessment:** ⚠️ Risk of data loss. Needs undo/redo.
**Improvement:** Add snapshotting (keep N generations); define merge strategy for conflicts.

## ADR-0005: Provider Modes
**Decision:** Support multiple LLM providers (Pi, Claude, GPT, etc.).
**Assessment:** ✅ Strategic flexibility. Missing interface.
**Improvement:** Define `IProvider` interface with capabilities (context, vision, tools, rate limits); add fallback chain.

## ADR-0006: Profiles (Lisp Mind vs Pi Default)
**Decision:** Separate profiles for Lisp-mind mode vs Pi-default mode.
**Assessment:** ✅ Good UX separation.
**Improvement:** Define profile schema (prompt, providers, mind config, vestige policy); add profile switching API.

## ADR-0007: Context Contributors
**Decision:** Pluggable context sources (files, git, web, etc.).
**Assessment:** ✅ High-value feature. No registration protocol.
**Improvement:** Define contributor lifecycle (register, init, update, teardown); add priority/conflict resolution.

## ADR-0008: Bounded RLM (Lisp Ops)
**Decision:** Implement bounded recursive Lisp macros in TS.
**Assessment:** ⚠️ High complexity. Scope creep risk.
**Improvement:** Phase to subset (quote, quasiquote, simple macros); defer full RLM to v2; add performance budget.

## ADR-0009: Soft Generations & Structured Surfaces
**Decision:** Versioned prompt/memory snapshots with UI surfaces.
**Assessment:** ✅ Strong UX vision. Missing diff/merge strategy.
**Improvement:** Define snapshot format (JSON patch, CRDT); add merge UI hooks; specify surface components (timeline, diff viewer).
