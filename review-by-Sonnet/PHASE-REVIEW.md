### Phase-03: Provider Widening
**Goal:** Support multiple LLM providers (not just Pi's default).
**Assessment:** ⚠️ ADR-0005 defines modes but no interface.
**Recommendation:** Define `IProvider` interface; add capability matrix (context window, rate limits, vision, tools).

### Phase-04: MCP Bootstrap
**Goal:** Run lisptc via MCP server.
**Assessment:** ✅ Clear milestone. Missing: performance SLOs.
**Recommendation:** Add SLOs (compile latency <2s, memory <500MB for 10k LOC).

### Phase-05: User Channel
**Goal:** Direct user input → Pi session.
**Assessment:** ✅ Straightforward I/O wiring. Low risk.

### Phase-06: Persistence Mind
**Goal:** SQLite/JSON store for working memory.
**Assessment:** ⚠️ No schema, no migrations, no concurrency model.
**Recommendation:** Add schema v1, migration fn, write-ahead log (WAL) mode for SQLite.

### Phase-07: Vestige Reify
**Goal:** Reify vestige (long-term memory) as Lisp data.
**Assessment:** ✅ Strong concept. Missing: serialization format, query API.
**Recommendation:** Define vestige schema (JSON-LD? EDN?); add query language (Datalog subset?).

### Phase-08: Optional Harden

**Assessment:** ⚠️ Catch-all phase. Needs sub-tasks.
**Recommendation:** Split into: profiling, caching, error handling, docs.

## Autolith Track (Phases 09–12)

### Phase-09: Context Contributors
**Goal:** Pluggable context sources (files, git, web, etc.).

**Assessment:** ⚠️ High complexity. Requires AST manipulation in TS.
**Recommendation:** Scope to subset (quote, quasiquote, simple macros); defer full RLM to v2.
