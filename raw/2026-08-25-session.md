## 3. Platform / Unix sockets Q&A

**Question:** Mentions of unix connectors/sockets in lisptc and/or Autolith — is migrating Pi to Linux a precondition?

**Answer: No.**

### Evidence

**lisptc**

- Pure TypeScript, Node ≥ 22.6
- Unix domain socket used only by optional **shared-session server** (`packages/repl` → session-server) so editor LSP + terminal can share one interpreter
- Pi extension path (`apps/pi`) runs interpreter **in-process** — no socket required for agent loop
- Shared session is multi-client DX, not deployment precondition

**Pi (earendil-works/pi)**

- Official Windows, macOS, Linux
- Dedicated Windows docs (Git Bash / PowerShell tool)
- npm global install and binaries; not Linux-only
- Experimental server packages may use Unix sockets; main coding agent does not require them

**Autolith**

- Linux, macOS, FreeBSD, NetBSD, OpenBSD
- **Not Windows**; SBCL live image; bubblewrap on Linux / seatbelt on macOS
- Inspiration only for Pi-Lisptc — not a runtime dependency

**Vestige**

- Local MCP memory; design does not force Linux-only host

### Practical matrix

| Goal | Need Linux? |
|------|-------------|
| Core phases 0–8 | No — macOS or Windows + Node fine |
| lisptc shared session (editor + REPL) | Unix socket preferred; Windows AF_UNIX or skip / in-process |
| Run Autolith itself | Yes (or macOS/BSD) |
| Optional gondolin-style micro-VM | Linux-oriented; optional isolation only |

### Decision recorded

Pi-Lisptc core = Pi extension + lisptc in-process + Vestige. Unix sockets are incidental. **Do not treat “migrate Pi to Linux” as a project precondition.**
